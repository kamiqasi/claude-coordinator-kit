  2. reply · 33 minutes later, queue included

    Two files. The tests pass. Deviation accepted.

And the kit's own gate. The worker's first commit of this kit included a .pyc holding host paths. The privacy gate caught it before anything left the machine; the commit was amended and every object scanned again.

What it holds to

  • your merge

    Every merge is yours. The worker opens PRs; it never merges them.

  • by token

    Matched by token, never guessed. The reply quotes the request's bird.

  • diff first

    The diff before the story. The review runs the checks itself.

  • final review

    Nothing public without your final look.

  • plain files

    Plain files, no server. Any shared folder carries them.

Ten commands

Grouped by where they sit in the loop: before while waiting after between sessions

  • /send

    before

    “Go with that.” Writes the request: decisions, steps, a Verify: command and where the worker must stop.

  • /next

    before

    “Where were we?” What waits on you, what’s in flight, and a weighted ranking of what’s next.

  • /wip

    while waiting

    “What’s in flight?” Everything in progress, issue first, each request’s state and age, and all the links in one block.

  • /while-we-wait

    while waiting

    “The worker’s busy.” Picks something the coordinator can do alone, and drops it when the reply lands.

  • /inbox

    after

    “Did it come back?” Reads the reply, reviews it, records a verdict, lists what waits on you.

  • /review-pr

    after

    “Is PR 42 ready?” Reads the diff before the worker’s story and runs the checks itself.

  • /merged

    after

    “I merged it.” Checks main holds what was reviewed, checks the rollout, queues the next phase.

  • /handoff

    between sessions

    “Let’s stop here.” Writes a handoff so the next session starts where this one ended.

  • /walkthrough

    between sessions

    “Walk me through it.” Plain words, the real trade-off, and commands to paste on the right host.

  • /ask

    between sessions

    “Ask me on the desk.” Posts one question, step or merge to a page you answer away from the terminal, then acts on your reply.

Install

As a Claude Code plugin; the repo is its own marketplace:

claude plugin marketplace add kamiqasi/claude-coordinator-kit
claude plugin install coordinator-kit@coordinator-kit

Or copy skills/* into ~/.claude/skills/; the README has both ways.

Setup

The skills hold no site facts. Copy coordinator-setup.example/SKILL.md to ~/.claude/skills/coordinator-setup/SKILL.md and fill in your shared folder, lanes, repos and checks.

What it is not

  • Not a framework. It’s Markdown that Claude Code reads.
  • No server. Any shared folder carries the files.
  • No agent hosting. You run both sessions.
